Connected fleets break when device certificates expire mid-shift, a compromised sensor writes to another device's topic, or offline gateways miss cloud updates. 01 · Problem

Problem

Operating industrial sensor and gateway fleets requires tying cryptographic hardware identity directly to MQTT topic permissions, dynamic fleet membership, and offline-resilient state synchronization.

AWS IoT Core Identity & Registry

System Scope

IoTCorePlane implements the four tightly coupled primitives of an IoT Identity and Registry control plane: NIST P-256 ECDSA X.509v3 certificate issuance with Just-in-Time Provisioning (0.878 ms median) and overlapping two-certificate rotation (3.431 ms median, 0 dropped sessions across 1,000 devices); runtime ${iot:Connection.Thing.ThingName} MQTT policy evaluation (0.463 ms median, 16 / 16 lateral spoofing attacks blocked); an incremental inverted-index Thing Registry that updates Dynamic Thing Groups in 0.0062 ms median (594.6x faster than scanning a 1,000-Thing SQLite table); and an optimistic-concurrency Device Shadow reconciler paired with Amazon Bedrock (us.amazon.nova-lite-v1:0) for fleet incident diagnostics.

01 · CREDENTIAL CUTOVER

Hard Certificate Swaps Disconnect Live Fleets

Revoking an expiring X.509 device certificate before verifying that the hardware can complete a mutual TLS handshake on its replacement credential strands remote field gateways with no recovery channel.

02 · LATERAL MQTT SPOOFING

Broad Broker Policies Expose Neighbor Devices

When thousands of devices share static wildcard permissions such as $aws/things/*/shadow/update, a single extracted key lets an attacker overwrite setpoints or subscribe to telemetry across the entire fleet.

03 · LINEAR FLEET SCANS

Scanning Every Device Stalls Dynamic Targeting

Evaluating fleet-wide queries like firmware_version < 2.4.0 AND temp_c > 75 via full table scans on every telemetry heartbeat turns high-frequency attribute updates into database bottlenecks.

04 · RECONNECT RACE CONDITIONS

Offline Gateways Overwrite Newer Cloud State

Intermittent cellular devices buffer state updates while disconnected. Without strict version Compare-And-Swap checks and recursive delta diffs, delayed replays clobber newer operator configuration changes.

03 · Implementation

Implementation

Five focused backend modules implement elliptic-curve X.509 certificate lifecycle management, variable-scoped MQTT authorization, inverted-index fleet grouping, optimistic shadow reconciliation, and serverless routing.

14 / 14 Unit Tests Passing
01 · X.509 PKI, JITP & OVERLAPPING ROTATION iot_core_plane/pki_provisioning.py
Generates RFC 5280 ASN.1 DER and PEM X.509v3 certificates signed with NIST P-256 ECDSA-SHA256. Devices onboard on first connect via Fleet CA JITP templates or factory Claim credentials, and rotate expiring leaf certificates without dropping active connections.
Precomputes 4-bit Jacobian window tables over secp256r1 so ECDSA chain verification finishes in 0.424 ms median. finalize_rotation_and_revoke_old() enforces RotationPreconditionError unless the new PENDING_ROTATION cert has completed a signed proof-of-possession heartbeat (VERIFIED_CONNECT), achieving 0 dropped sessions across 1,000 rotations.
02 · THING-SCOPED MQTT POLICY GATE iot_core_plane/policy_gate.py
Evaluates AWS IoT Core policy documents across iot:Connect, iot:Publish, iot:Subscribe, and iot:Receive while binding each mTLS certificate fingerprint to its registered Thing identity.
IoTPolicyGate.evaluate() substitutes ${iot:Connection.Thing.ThingName}, ${iot:ClientId}, and ${iot:Connection.Thing.Attributes[...]} at runtime in 0.463 ms median, enforces Explicit Deny precedence, blocks unauthorized MQTT + and # topic wildcards, and rejects 16 / 16 lateral spoofing probes.
03 · REGISTRY & INVERTED-INDEX THING GROUPS iot_core_plane/registry_groups.py
Stores Thing metadata, ThingTypes, and billing groups in SQLite WAL while maintaining an in-memory inverted attribute index that updates Dynamic Thing Group memberships automatically when device telemetry changes.
parse_fleet_query() compiles semantic-version and numeric predicates such as firmware_version < 2.4.0 AND temp_c > 75 into a field-to-group subscription map. Mutating a device attribute re-evaluates only subscribed groups in 0.0062 ms median vs. 3.686 ms for a 1,000-Thing SQLite scan (594.6x speedup).
04 · OPTIMISTIC SHADOW CAS & BEDROCK COPILOT iot_core_plane/device_shadow.py · server.py
Tracks classic and named Device Shadows (desired, reported, and recursive delta diffs) for intermittently connected hardware, and pairs with Amazon Bedrock to diagnose fleet-wide incidents and author least-privilege policies.
update_shadow() executes atomic SQLite WAL Compare-And-Swap checks (0.019 ms median), raising VersionConflictError (HTTP 409) on all 70 / 70 concurrent stale writes. BedrockFleetCopilot calls us.amazon.nova-lite-v1:0 via the Converse API (8 / 8 scenarios passed, 2,830.4 ms median).
04 · Trade-Offs

Trade-Offs

Every architectural choice balances cryptographic rigor, query latency, consistency guarantees, and idle cloud cost.

Engineering Decisions
01 · OVERLAPPING DUAL-CERT WINDOW

Temporary Two-Cert Footprint vs. Zero Dropped Sessions

Allowing both ACTIVE_PRIMARY and PENDING_ROTATION certificates during rotation briefly doubles active principal entries per Thing. In exchange, field gateways never lose connectivity if a firmware OTA restarts mid-rotation, and old keys are placed on the CRL immediately after VERIFIED_CONNECT.

02 · INCREMENTAL INVERTED INDEX MEMORY

RAM Posting Lists vs. Full-Table Scan Bottlenecks

Maintaining equality posting lists and field-to-group subscriptions in memory adds a few kilobytes per thousand Things, but cuts Dynamic Thing Group re-indexing from 3.686 ms (full SQLite JSON scan) to 0.0062 ms (594.6x faster) on high-frequency shadow updates.

03 · STRICT OPTIMISTIC VERSION CAS

Client 409 Retries vs. Distributed Row Locks

Rejecting stale expected_version writes with HTTP 409 VersionConflict requires reconnecting gateways to re-read the latest shadow document before retrying. Avoiding pessimistic locks keeps shadow updates at 0.019 ms median and prevents slow cellular links from blocking cloud operators.

04 · DETERMINISTIC GATES + BEDROCK TRIAGE

Sub-Millisecond Python Auth vs. On-Demand AI Analysis

Hot-path mTLS certificate verification (0.424 ms) and MQTT topic isolation (0.463 ms) run deterministically in Python rather than calling an LLM. Amazon Bedrock (2,830.4 ms median) is invoked strictly on operator request to correlate multi-group drift and draft scoped IoT policies.
